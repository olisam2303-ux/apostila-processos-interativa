Atividade 1 — "Modelo em cascata na prática"

Contexto

Uma empresa vai desenvolver um sistema de controle de pedidos. Prazo curto, orçamento limitado, requisitos definidos e (segundo o cliente) sem mudanças. A equipe escolhe o modelo cascata.

Base: apostila, Capítulo 15. Fases oficiais (aula S15A1): requisitos, análise, projeto, implementação, testes, manutenção. Desenhem o fluxograma no draw.io.

Este é o formato esperado no draw.io: uma seta só para baixo, entre cada par de caixas — nenhuma seta volta para uma fase anterior.

Como preencher esta atividade

  1. 1Preencham a identificação do grupo.
  2. 2Desafio 1: expliquem cada fase em uma frase e desenhem o fluxograma no draw.io igual ao diagrama de referência acima.
  3. 3Desafios 2 a 5: sigam na ordem — cada um olha o modelo cascata de um ângulo diferente (erro interno, quando funciona bem, mudança do cliente, avaliação crítica).
  4. 4Confiram o checklist e gerem o PDF (lembrem de desmarcar Cabeçalhos e rodapés).

Identificação

Desafio 1 — As fases do modelo cascata

Objetivo de cada fase em uma frase; por que uma fase só começa após a anterior; o que acontece se uma fase for mal executada. Colem a imagem do fluxograma do draw.io (6 caixas de cima para baixo, sem setas de retorno).

Cada fase depende do resultado da anterior (ex.: não dá para desenhar o projeto sem saber os requisitos) — é por isso que o fluxo do diagrama só tem setas para baixo.

Desafio 2 — Erro de entendimento da própria equipe

Um requisito foi mal entendido; percebe-se só na implementação. O erro é interno.

Desafio 3 — Quando o cascata funciona bem

Desafio 4 — Mudança solicitada pelo cliente

Diferente do Desafio 2: o produto não estava errado; o cliente mudou de ideia com a implementação em andamento.

Atividade 2 — "Modelos incremental e evolutivo"

Contexto

Uma startup desenvolve um app de organização de estudos para o ensino médio. Objetivo inicial: registrar matérias e tarefas. Com o uso surgem lembretes automáticos, gráficos de desempenho, integração com calendário — os requisitos mudam.

Base: apostila, Capítulo 15 (tabela de comparação dos três modelos). Desenhem os dois modelos no draw.io.

Desenhem exatamente essas duas formas no draw.io: 3 mini-ciclos em sequência (incremental) e o laço com o losango de decisão (evolutivo).

Como preencher esta atividade

  1. 1Preencham a identificação do grupo.
  2. 2Etapa 1: expliquem por que os requisitos ainda não estão 100% definidos neste projeto.
  3. 3Etapa 2: planejem as 3 versões incrementais, na ordem que já está sugerida pelo contexto.
  4. 4Etapas 3 e 4: expliquem o ciclo evolutivo com feedback e como as fases clássicas se repetem dentro de cada ciclo.
  5. 5Etapa 5: desenhem os dois diagramas no draw.io, iguais à referência acima.
  6. 6Etapa 6: justifiquem a escolha usando a tabela do Capítulo 15.
  7. 7Confiram o checklist e gerem o PDF (lembrem de desmarcar Cabeçalhos e rodapés).

Identificação

Etapa 1 — Compreensão do problema

Etapa 2 — Planejamento incremental

O contexto já sugere a ordem: registrar matérias/tarefas → lembretes → gráficos + calendário. Para cada versão, o que entrega e por que essa ordem.

Cada versão precisa ser útil por si só (o usuário já consegue usar algo), não uma peça incompleta que só funciona quando somada às outras.

Etapa 4 — Relação com as fases clássicas

Em 3 a 4 frases: como requisitos, análise, projeto, implementação, testes e manutenção acontecem dentro de cada ciclo (várias vezes), e não uma única vez.

Etapa 5 — Diagramas no draw.io

Página 1: incremental (3 mini-ciclos em sequência). Página 2: evolutivo (esboço → protótipo → retorno → losango "atende?": não volta a "refinar", sim segue para o fim).

Etapa 6 — Justificativa da escolha

Objetivos

  • Aplicar o modelo em cascata a um cenário com requisitos estáveis, descrevendo as seis fases (requisitos, análise, projeto, implementação, testes, manutenção) em um fluxograma sem retorno.
  • Comparar como o modelo cascata reage a um erro interno de entendimento e a uma mudança de escopo pedida pelo cliente.
  • Planejar um sistema com requisitos incertos em versões incrementais, cada uma entregando valor, e aplicar o modelo evolutivo com ciclos de esboço, protótipo e refinamento.
  • Justificar a escolha de um modelo de processo comparando cascata, incremental e evolutivo.
